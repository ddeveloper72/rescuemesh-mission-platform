# Generated Mission Media

This directory contains synthetically generated mission media for simulation demos.

## Directory Structure

```
media/generated/
├── images/          # Generated PNG images
├── audio/           # Generated WAV audio files
└── spectrograms/    # Audio visualization PNGs
```

## Overview

RescueMesh uses a **simulation-first approach** to mission media. Instead of requiring S3/object storage, the platform generates synthetic media on demand using Python:

- **Images** - Generated with Pillow (low-light, thermal, underwater, industrial, dusty rubble)
- **Audio** - Generated with Python's wave module (knocking, tapping, voice-like, ambient)
- **Spectrograms** - Visual frequency analysis of audio clips

## Lazy Generation

Media files are generated **only when requested** and cached to disk:

1. Frontend requests media via API endpoint (e.g., `/api/v1/generated-media/{media_id}/preview/`)
2. Backend checks if file exists in cache
3. If exists, serve cached file
4. If not, generate file, save to cache, and serve

This approach:
- Keeps storage usage minimal
- Speeds up subsequent requests
- Works offline without cloud dependencies
- Supports Docker deployment easily

## Cache Management

**View cache:**
```bash
ls -lh media/generated/images/
ls -lh media/generated/audio/
ls -lh media/generated/spectrograms/
```

**Clear cache:**
```bash
# Remove all generated media (will be regenerated on next request)
rm -rf media/generated/images/*
rm -rf media/generated/audio/*
rm -rf media/generated/spectrograms/*
```

**Docker:**
```dockerfile
# Mount as writable volume
VOLUME /app/media/generated
```

## Generated vs Real Media

### Demo Mode (Current)
- Synthetic media generated by Python
- No S3 or object storage required
- Cached locally in this directory
- Perfect for development and demos

### Real Operational Mode (Future)
- Actual mission media stored in S3
- Database stores metadata and references
- Same API endpoints work for both modes
- Seamless transition by changing backend config

## Media Types

### Images (PNG)

- **Low-light scenes** - Dark environments with sensor noise
- **Thermal frames** - Heatmap-style images with hotspot detection
- **Underwater** - Murky blue-green tinted images with particles
- **Industrial** - Pipe surfaces, corrosion, rust patterns
- **Dusty rubble** - Collapsed structure with dust particulate
- **Last-good-frame** - Signal-degraded image with "SIGNAL LOST" overlay

All images include:
- Timestamp overlay
- Confidence percentage badge
- Signal quality badge
- Text annotations
- Context-appropriate styling

### Audio (WAV, 44.1kHz, Mono, 16-bit)

- **Knocking** - 3-5 knocks with low-frequency impact sounds
- **Tapping** - Higher frequency, sharper impacts (SOS patterns supported)
- **Voice-like** - Text-to-speech generated robotic distress messages (using pyttsx3) or waveform fallback
- **Static** - White noise with low-frequency rumble
- **Ambient** - Cave drips, underwater muffled sounds, industrial hum

The voice-like audio uses **text-to-speech (TTS)** technology to generate realistic but clearly synthetic/robotic human-like audio. Messages include:
- Distress signals ("Assistance requested. Unit status compromised.")
- Status updates ("Automated status update. Unit operational.")
- Alert notifications ("Anomaly detected. Sensor readings abnormal.")

All TTS messages are designed to be obviously artificial/robotic to avoid any ethical concerns while providing realistic audio patterns for demo purposes. Falls back to waveform-based generation if pyttsx3 is unavailable.

### Spectrograms (PNG)

Visual representations showing:
- Frequency distribution (vertical axis)
- Time progression (horizontal axis)
- Intensity as color brightness
- Annotations for detected patterns

## File Naming Convention

- Images: `{mission_id}-{type}-{sequence}.png`
- Audio: `{mission_id}-{type}-{sequence}.wav`
- Spectrograms: `{mission_id}-{type}-{sequence}_spec.png`

Examples:
- `demo-cave-rescue-voice-audio-001.wav`
- `demo-collapsed-building-thermal-001.png`
- `demo-cave-rescue-voice-audio-001_spec.png`

## Dependencies

- **Pillow** - Image generation and manipulation
- **wave** (stdlib) - WAV audio file generation
- **struct** (stdlib) - Binary audio data formatting
- **math/random** (stdlib) - Waveform generation
- **pyttsx3** - Text-to-speech for voice-like audio (optional, falls back to waveform generation)

No external binary dependencies (FFmpeg, ImageMagick, etc.) required.

## Technical Details

### Image Generation

Uses Pillow to:
- Create base noise images
- Apply gradients and filters
- Draw shapes and patterns
- Add text overlays
- Simulate sensor artifacts

### Audio Generation

Uses Python's wave module to:
- Generate sine waves at specific frequencies
- Mix multiple frequency components
- Apply ADSR envelopes
- Add ambient noise
- Create realistic impulse sounds

### Spectrogram Generation

Simplified visualization without FFT:
- Stylized frequency/time representation
- Pattern-based rendering
- Realistic appearance for demos
- No scipy/matplotlib dependency

## Performance

Typical generation times (on modern hardware):
- Image: 50-200ms
- Audio (2-3 seconds): 100-300ms
- Spectrogram: 100-250ms

First request generates and caches.
Subsequent requests serve cached file instantly.

## Troubleshooting

**Images appear blank or corrupted:**
- Check Pillow installation: `pip show Pillow`
- Verify media directory permissions
- Clear cache and regenerate

**Audio files don't play:**
- Confirm WAV format (44.1kHz, Mono, 16-bit)
- Check file size (should be >1KB)
- Try different audio player

**Permission errors:**
- Ensure media/generated/ is writable
- In Docker, mount with correct permissions
- Check user ownership

**Cache not clearing:**
```bash
# Force delete (Linux/Mac)
sudo rm -rf media/generated/*

# Windows
rmdir /s media\generated
mkdir media\generated\images media\generated\audio media\generated\spectrograms
```
